# WVST 审查与文档升级（2026-09-07）

本轮重点审查 Web SDK transport、Demo 生命周期、文档构建与部署边界，并运行 Rust workspace 现有测试和静态检查。这不是所有第三方插件、操作系统与真实音频设备的完整兼容性认证。

## 已修复的问题

| 优先级 | 触发条件与影响 | 修复位置与行为 |
| --- | --- | --- |
| P1 | 预渲染的 Demo 不经过 SvelteKit server hook，静态部署和 preview 丢失 COOP/COEP，导致 SharedArrayBuffer 不可用 | `docs/_headers` 为 Cloudflare 静态文件添加隔离头；`docs/vite.config.ts` 对 dev 与 preview 都设置隔离头 |
| P2 | WebSocket 已关闭后调用 RPC 或发送音频，浏览器静默丢弃 send，Promise 永远 pending | `packages/wvst-web/src/client/transport.ts` 在发送前检查 OPEN，明确 reject |
| P2 | 二进制 send 抛异常后，失败请求仍占据 FIFO，下一个响应被错误消费 | 同上：发送异常时移除对应 pending；RPC 发送异常也清理 pending map |
| P2 | 文本消息是合法 JSON `null` / 数值等时，`in` 运算抛出未处理异常 | 同上：丢弃非对象或数组响应 |
| P2 | Demo instance.create 成功但 instance.start 失败，catch 没有实例句柄可清理 | `WVSTRackDemo.svelte` 立即保存创建结果，失败时停止音频流并销毁实例 |
| P2 | Demo 断开后重新播放，对同一个 HTMLMediaElement 再次调用 createMediaElementSource，抛 InvalidStateError | 同上：重连复用媒体源与 AudioContext，组件销毁时才释放图；再次播放恢复电平刷新 |
| P2 | Svedocs CLI 已输出静态 OG 文件，旧 endpoint 强制 prerender 导致 SvelteKit unseen-route 构建错误 | `docs/src/routes/og/[...path]/+server.ts` 使用自动 prerender，兼容 CLI 生成与 `--no-og` 两条构建路径 |

Transport 新增四个行为回归测试；修复前复现两个超时和两个未处理异常，修复后全部通过。Demo 生命周期通过 Chromium、模拟 WebSocket Bridge、失败的 instance.start 响应和 WAV 播放验证，不代表真实插件处理验证。

本轮初次审查保留了超过 600 行的旧 Demo 组件；随后的 [Studio 翻新](studio-redesign-2026-09-07.md) 已将 graph 管理和引导界面抽离，主组件降至 600 行以内。
